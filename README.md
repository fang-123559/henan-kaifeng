# 开封美食地图

将 **62 张小红书帖子与评论区截图**逐条识别，整理为 **217 条地点记录**，用于规划开封逛吃路线。记录以美食为主，也包含景点、地标、住处和交通点。

原版页面提供真实地图、可独立滚动的清单、搜索与筛选、地点详情、来源截图、名称地址复制和直线距离排序。无需前端安装或打包。

## 快速开始

### 只看地图

打开上面的在线入口；也可以下载仓库，保持目录结构不变，双击 `index.html`。

- 页面 CSS、JavaScript、Leaflet 和地点数据已内联在 HTML 中。
- **地图底图需要联网**，瓦片来自高德；离线仍可查看清单和地点数据。
- **来源截图未内联**。查看原图时需保留同级的 `图片素材/原图/`，只传 HTML 会缺少截图。
- 网页定位需要浏览器授权以及 HTTPS 或 localhost。距离使用 Haversine 公式计算，是球面直线距离，不是步行或驾车路线。

### 从当前数据重建

需要 Python 3。此构建步骤仅使用 Python 标准库和仓库内的 Leaflet 文件，无需安装前端依赖。

```bash
git clone https://github.com/fang-123559/henan-kaifeng.git
cd henan-kaifeng
python 脚本/07_build_html.py
```

构建会覆盖根目录 `index.html`，输入是当前 `data.json`。不要把历史脚本 `01 → 13` 当成日常构建命令连续执行：它们记录素材处理和数据迁移过程，部分步骤会改写数据。

若要在 localhost 下使用网页定位，可在仓库根目录启动：

```bash
python -m http.server 8000
```

然后在浏览器打开 `http://localhost:8000/`。

## 数据与可信度

当前仓库的数据快照为 **217 条**，其中有坐标 **183 条**、无坐标 **34 条**；包含 **46 种类型**和 **17 个区域**。

| 原版页面统计档位 | 数量 | 含义 |
|---|---:|---|
| 精确定位 | 113 | 有坐标、`loc` 不是 `approx`，且未设置 `offmap`；这是渲染分类，不等于全部都有完整精度证据 |
| 区域近似 | 70 | `loc="approx"`，按所属片区锚点及微偏移标注 |
| 未定位 | 34 | 无可用坐标，留在清单，不落点 |

原始字段中 `loc="exact"` 为 **33 条**、`loc="approx"` 为 **70 条**，其余 **114 条**未标注 `loc`。原版把未标精度但有坐标的记录归入“精确定位”，因此不要把实心点直接理解为已逐条证明的精度等级。唯一星标为公开版示意住处，说明见下节。

### 主要字段

| 字段 | 用途 |
|---|---|
| `id` / `n` | 唯一编号 / 地点名称 |
| `ty` / `ar` | 类型 / 片区 |
| `lat` / `lng` | 经纬度，可为 `null`；坐标需与高德底图的 GCJ-02 坐标系匹配 |
| `ad` / `ds` | 地址 / 推荐菜或特色 |
| `src` / `img` | 来源文字或图号 / 原帖截图的相对路径 |
| `rm` | 网友原话与编辑校勘注；部分记录用全角 `｜` 分隔 |
| `loc` | 坐标精度来源标记 |
| `star` / `offmap` | 唯一星标 / 是否不在地图标注 |

`data.json` 是构建时的唯一数据源；成品 HTML 内联其快照，修改数据后需要重新构建。215 条记录引用来源图片，涉及 46 个不同文件；素材目录保留全部 62 张原图。

数据并非实时商户目录，不保证店名、分店、营业时间或经营状态仍与截图一致；到店前请另行确认。文档维护日期为 **2026-10-12**，不代表全部商户在该日重新核验。

## 公开演示与自用地图

**本仓库与在线链接是公开演示版**，住处记录已处理：

| 项目 | 公开版处理 |
|---|---|
| 店名 | 泛化为“住处” |
| 地址 | 降到路段级 |
| 来源 | 使用“行程主人提供” |
| 坐标 | 偏移约 500m，不指向真实门店 |
| 星标 | 保留，展示唯一锚点与距离基准功能 |

因此，以公开版住处为基准算出的距离仅供示意；它与真实住处距离会有差异，不应用于定位真实住处。

**这不是用户自行生成地图的默认要求。** 用户自用地图默认保留真实店名、地址和坐标，以保证星标与距离基准可用；对外分享前再选择处理方式。具体流程见 [trip-map-builder 的 SKILL.md](https://github.com/fang-123559/trip-map-builder/blob/main/SKILL.md)。

### 已知限制

- 原版配色表未覆盖 8 个类别，共 16 条记录使用兜底灰；本轮文档更新不改变配色。
- “区域近似”只适合片区规划，不能当作商户精确门址。

### ① 素材输入与预处理

原始素材来自两处：剪贴板截图目录与浏览器下载目录。前者默认取 `~/clipboard-images`，后者默认取 `~/Downloads`，可用环境变量 `KAIFENG_CLIP_DIR` / `KAIFENG_GOOGLE_DIR` 覆盖。

| 脚本 | 做什么 |
|---|---|
| `01_prepare.py` | 按给定顺序复制前 50 张到 `图片素材/原图/`，并生成放大版到 `图片素材/放大/` |
| `02_crop.py` | 裁出「评论区 / 正文侧栏」并放大 —— 便于逐字看 |
| `03_crop_mid.py` | 「居中图片型」截图（表格、备忘录）裁中心文字区 |
| `04_crop_seg.py` | 表格 / 备忘录类**纵向切段**放大，避免被压缩成一条 |
| `05_batch2.py` | 第二批 12 张，重复上述复制、裁剪、放大 |

> 产物：`图片素材/原图/` 共 **62 张**（14 MB），放大版 186 张（81 MB，仅为识别服务，非交付物）。

### ②③ 识别与录入

**这一步没有 OCR 程序，是人工放大逐字读图**，再结构化为 Python 列表。这是全流程最耗时的一环，也是数据准确性的来源。

| 脚本 | 做什么 |
|---|---|
| `06_build_data.py` | 把识别结果硬编码为列表 `S`（名称 / 类型 / 区域 / 经纬度 / 地址 / 推荐菜 / 来源图号 / 补充），生成初版 `data.json` 与首版 HTML |
| `08_update_data.py` | 按**逐图核对**结果修正、补充 `data.json` |
| `10_add_batch3.py` | 第三批：补录核对中新发现的条目，并为既有条目补备注 |

### ④ 数据净化

| 脚本 | 做什么 |
|---|---|
| `09_dedup.py` | 去重：合并同一实体的重复录入（原文件备份为 `data.raw.bak.json`） |
| `11_add_coords.py` | 补坐标。**两类来源，绝不混同**：<br>· `DIRECT` —— 腾讯地图检索到的真实 POI，精确坐标，`loc="exact"`<br>· `APPROX` —— 无独立 POI（夜市摊 / 园内摊 / 品类名），按所属区域锚点 + **确定性微偏移**，`loc="approx"`，页面以空心点标注，**绝不冒充精确位置** |
| `12_hotel_fix.py` | 住宿标注收敛：只有 `住处` 带 `star=true`（全图唯一星标）；推荐列表里提到的其他酒店打 `offmap=true`（保留数据含来源，但不出点） |
| `13_delete_offmap_hotels.py` | 删除无关酒店并**重排 id 使连续**（1..N），保持既有不变式 |

> 产物：`data.json` —— **217 条，13 个字段**，是整个项目的唯一数据源。

### ⑥ 新版《汴京食帖》构建

`21_build_shitie.py`（约 2,050 行，**单脚本产出单文件**）读同一份 `data.json`，输出 `汴京食帖.html`。

四个硬约束决定了它的实现方式（脚本头部原文）：

1. **不联网** —— 自绘墨图，经纬投影 + 数据生成墨晕，断网照常可用
2. **不造假** —— 每个视觉变量都能追溯到真实字段：墨分三色 = `loc` 三态；城的轮廓 = 183 个落墨点密度洇开
3. **不改旧版** —— 只新增输出，不动原有文件
4. **三色定调** —— 宣纸 / 墨 / 朱砂，朱砂仅用于落印与选中

构建脚本内含全部数据内联、CSS、JS、音色合成，并在构建时**逐项断言**：

- **46 个 `ty` 取值**全部归入 9 个品类组（漏一个就报错）
- **17 个 `ar` 取值**全部归入 10 个市井分组，且分组计数之和 = 217
- 住处（无 `loc` 字段）必须走 `star` 分支归「确址」，与 JS 端**双端同源**

### ⑦ 新版验证

| 脚本 | 做什么 |
|---|---|
| `22_probe_shitie.py` | 视觉与控制台探针，**15 档**：`open` / `note` / `bag` / `no` / `gate` / `deep` / `scope` / `scope2` / `tl` / `tl2` / `hotelnote` / `locate` / `hotel` / `labels` / `snd`，另有 `mobile`（窄屏 520×900 特例）。无头 Chrome 截图 + 捕获 JS 错误 |
| `23_verify_shitie.py` | 功能与几何核验，**A–Q 十七节**：投影真实性（屏幕像素↔haversine 实距，误差 <2%）、数量、墨色闸门、品类、市井、检索、交互可达性、住处恒显、标签零相交、视野不被夺走、朱线由按钮触发…… |

> 两条通用经验：**无头 Chrome 里 `requestAnimationFrame` 几乎不触发**，探针必须把 rAF 换成 `setTimeout(cb,16)`（且 22 与 23 **必须共用同一套替身**）；**凡依赖 rAF 落定的断言，一律改成「反复触发 ＋ 轮询复核」，并把收敛轮数当健康指标**。
